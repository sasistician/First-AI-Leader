底层数学 · 第1部分（共4部分） 04 — 11
你早已熟悉的基础构件

每一个神经网络，最初都是你早已见过的东西。

步骤一 y = wx + b 线性回归 输入的加权和，再加上一个偏置项。这是最简单的模型——用一条直线去拟合数据。
→
步骤二 + activation 非线性 对输出做"压缩"处理（ReLU、sigmoid 等），让模型能够学习曲线与相互作用关系，而不仅仅是直线。
→
步骤三 stack layers 深度网络 将这样的结构串联起几十层。每一层都在学习更抽象一级的模式。
→
步骤四 + attention Transformer 加入一种新的层类型——注意力机制（attention），再加上一种编码词序的方法。这就是当今大语言模型背后的关键要素。

并没有什么魔法——只是线性代数，叠得足够深，再加上一种新的层类型。接下来，我们就看看这个新的层类型。

改变一切的论文 · 第2部分（共4部分） 05 — 11
2017年 ·《attention is all you need》· google research

在2017年之前，模型是按顺序逐字阅读的，就像读一条磁带一样。

  • 2017年之前——RNN 与 LSTM：逐个、按顺序处理 token。训练速度慢，而且会"遗忘"较早之前的上下文。
  • 2017年——Transformer：完全用自注意力机制（self-attention）取代了循环结构——每个 token 都被并行处理，并且可以直接与任意距离之外的其他 token 建立联系。
  • 结果：训练终于可以规模化——更多数据、更多算力、更多参数——直接催生了 GPT、Claude，以及此后的一切。

正是这一项架构上的改变，造就了过去十年 AI 的一切可能。

注意力机制如何运作 · 第2部分（共4部分） 06 — 11
直观理解，无需数学

每个词都会看向其他所有词——并决定哪些才是重要的。

The agent fixed the bug in the file

在这句话中，"bug" 一词会强烈关注 "agent"、"fixed" 和 "file"——这些词共同赋予了它在句中的含义——而几乎不会关注 "the"。这就是注意力机制：每个词都会自行判断,其他哪些词与自己相关。

  • 每个词都会提出一个问题——"我需要理解什么才能弄懂自己？"——这就是查询（Query）。
  • 每个词同时也会"展示"自己能提供什么——"这就是我所代表的内容"——这就是键（Key）。
  • 当某个词的"展示内容"与问题匹配时，就会获得更多关注，并按相关性加权——由此流动的就是值（Value）。
  • 将这一过程在许多层中重复进行，模型就不只是在预测下一个词——它正在构建对整个上下文的实际理解。而这正是它能够决定下一步该做什么的原因。
过渡篇 · 第3部分（共4部分） 07 — 11
从自动补全到自主行动

归根结底，Claude 本质上仍然只是在预测下一个词。那它究竟是如何编辑文件、运行测试、修复 bug 的呢？

  • 小规模的下一词预测 → 自动补全。
  • 大规模的下一词预测，并在合适的数据（代码、推理过程、对话）上训练 → 规划、推理、可运行的代码。
  • 但模型本身无法执行任何操作——它只能生成文本。
  • 必须有某种机制，将这些文本转化为真实的行动：读取文件、运行命令、调用工具，并将结果反馈回去。

这个"某种机制"就是智能体执行框架（agent harness）——也是我们接下来要讲的内容。

执行框架 · 第4部分（共4部分） 08 — 11
模型与智能体之间缺失的那一环

模型负责预测文本。执行框架则将预测转化为行动——并将结果反馈回去。

01 感知 Perceive 读取当前状态——你的提示词、项目文件、终端输出，以及目前为止的结果。
02 规划 Plan 模型决定下一步该做什么——使用哪个工具、写什么代码、运行什么命令。
03 行动 Act 执行框架真实执行这一步——编辑文件、运行命令、调用 API。
04 观察 Observe 结果作为新的上下文反馈回去——循环再次开始。
↻ 感知 → 规划 → 行动 → 观察 → 循环往复，直至任务完成
解构 · 第4部分（共4部分） 09 — 11
五大组成部分，一种模式

每一个智能体执行框架——无论是 Claude Code 还是其他——都由同样的五个部分构成。

01模型 Model
是什么

大语言模型本身。

在循环中的角色

负责生成"规划"步骤——以自然语言或结构化工具调用的形式，决定下一步该做什么。

02工具 Tools
是什么

执行框架可以调用的函数。

在循环中的角色

读写文件、运行 shell 命令、调用 API、搜索网络——对应"行动"步骤。

03上下文 Context
是什么

模型当前能够"看到"的内容。

在循环中的角色

你的提示词、项目文件、CLAUDE.md、对话历史——对应"感知"步骤。

04权限 Permissions
是什么

规定执行框架在无人监督时可以做什么的规则。

在循环中的角色

只读还是可写、自动批准还是先询问——这是对"行动"步骤的护栏。

05记忆 Memory
是什么

在不同会话之间持续保留的内容。

在循环中的角色

保存的事实、偏好、项目状态——比任何单次循环都更持久的上下文。

我们将在第2周深入讲解上下文（Context），第3周讲工具 / Skill，第4周讲MCP，第5周讲权限 / 护栏机制。今天，先了解整体地图。
